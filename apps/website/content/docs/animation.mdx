Streamdown supports per-word streaming animation through the `animated` prop. Words fade in as they mount. After streaming ends, scheduled words finish animating before their wrappers are removed, leaving plain text in completed messages.

## Enabling animation

Import the animation CSS and set the `animated` prop:

```tsx title="app/page.tsx"
import { Streamdown } from "@lofcz/streamdown";
import "@lofcz/streamdown/styles.css";

export default function Page() {
  return (
    <Streamdown animated isAnimating={status === "streaming"}>
      {markdown}
    </Streamdown>
  );
}
```

The `isAnimating` prop controls streaming. When it turns `false`, the browser's pending text animations drain before the animate plugin is removed. With `smooth`, animation remains active while buffered text is being revealed.

## Loading the animation

The engine is its own module, `@lofcz/streamdown/animate`, usable with both the main and `core` entries. Streamdown starts loading it after a streaming-mode component with `animated` set first commits on the client, even while `isAnimating` is `false`. Components without `animated`, and static history, never request it. Until it arrives, text renders without the fade; already-visible words stay settled and later text animates. A stream that ends before loading finishes is not replayed.

Every instance shares the load. Failed loads leave text readable; later updates can retry after 1, 2, and 4 seconds, with a maximum of four attempts.

To animate from the very first render, pass the module as a plugin as well as setting `animated`. It then ships with your bundle:

```tsx title="app/page.tsx"
import { Streamdown } from "@lofcz/streamdown";
import { animate } from "@lofcz/streamdown/animate";
import "@lofcz/streamdown/styles.css";

export default function Page() {
  return (
    <Streamdown
      animated
      isAnimating={status === "streaming"}
      plugins={{ animate }}
    >
      {markdown}
    </Streamdown>
  );
}
```

## Loading the animation

The word fade ships in its own chunk. A component with `animated` set starts loading it after it first commits on the client, even while `isAnimating` is `false`. Every component shares that one load, and components that never set `animated` never request it. Until it arrives, text renders without the fade. The words on screen when it arrives stay as they are, and only text that streams in after them fades in, so on a cold start the first words of the first animated message appear without the fade. If the chunk fails to load, text keeps rendering without the fade and later updates can retry the load with bounded backoff.

## How it works

The animation is a rehype transformer that:

1. Walks the HAST tree, visiting text nodes
2. Splits each text node into per-word `<span>` elements with `data-sd-animate`
3. Sets CSS custom properties for animation name, duration, and easing
4. Skips text inside `pre`, `svg`, `math`, and `annotation` elements (inline `code` is animated with surrounding prose)

React's reconciliation ensures only newly-mounted spans trigger the CSS animation. Combined with a short default duration (150ms), this makes batch token arrivals look smooth rather than "chunky."

## Animation types

Three built-in animations are included in `styles.css`:

### fadeIn (default)

A simple opacity transition from invisible to visible.

```tsx
<Streamdown animated={{ animation: "fadeIn" }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>
```

### blurIn

Combines opacity with a blur-to-sharp transition. Works well with fast-streaming models where many tokens arrive at once — the blur masks the batch appearance better than pure opacity.

```tsx
<Streamdown animated={{ animation: "blurIn" }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>
```

### slideUp

Words fade in while sliding up 4px, creating a subtle rising effect.

```tsx
<Streamdown animated={{ animation: "slideUp" }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>
```

## Configuration

Pass an options object to `animated` to customize animation behavior:

```tsx title="app/page.tsx"
import { Streamdown } from "@lofcz/streamdown";
import "@lofcz/streamdown/styles.css";

export default function Page() {
  return (
    <Streamdown
      animated={{
        animation: "blurIn",  // "fadeIn" | "blurIn" | "slideUp" | custom string
        duration: 200,         // milliseconds (default: 150)
        easing: "ease-out",    // CSS timing function (default: "ease")
        sep: "word",           // "word" | "char" (default: "word")
      }}
      isAnimating={status === "streaming"}
    >
      {markdown}
    </Streamdown>
  );
}
```

### Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `animation` | `string \| AnimationEffect` | `"fadeIn"` | Animation name. Built-in: `fadeIn`, `blurIn`, `slideUp`. Custom strings are prefixed with `sd-`. Also accepts an [effect](#animation-effects). |
| `duration` | `number` | `150` | Animation duration in milliseconds. |
| `easing` | `string` | `"ease"` | CSS timing function. |
| `sep` | `"word" \| "char"` | `"word"` | Split text by word or character. |
| `stagger` | `number` | `40` | Delay between words in milliseconds. Defaults to `0` with `smooth`; an explicit value is retained. |
| `maxBacklogMs` | `number` | `320` | Soft limit on how far the animation timeline runs ahead of wall-clock time. |

### Character-level animation

Set `sep: "char"` to animate each character individually instead of whole words:

```tsx
<Streamdown animated={{ animation: "fadeIn", sep: "char" }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>
```

This creates a typewriter-like effect but generates more DOM nodes. Use it sparingly.

## Custom animations

Define your own `@keyframes` and reference them by name:

```css title="app/globals.css"
@keyframes sd-myCustomAnimation {
  from {
    opacity: 0;
    transform: scale(0.95);
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}
```

```tsx
<Streamdown animated={{ animation: "myCustomAnimation" }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>
```

The animation name is automatically prefixed with `sd-`, so define your keyframes as `sd-yourName`.

## Animation effects

`animation` also accepts an effect object. An effect bundles a keyframes name with the per-word behavior those keyframes need, such as a scattered reveal order or attributes for your CSS to draw. [`@streamdown/effects`](/docs/plugins/effects) provides ready-made effects.

```tsx
import type { AnimationEffect } from "@lofcz/streamdown";

const shimmer: AnimationEffect = {
  name: "shimmer", // uses @keyframes sd-shimmer
  duration: 300, // default; animated.duration overrides it
  scatter: 120, // up to 120 ms extra delay per word, in a stable random order
  decorate: (text, seed) => ({ "data-shimmer": text }), // extra data-* attributes
};

<Streamdown animated={{ animation: shimmer }} isAnimating={status === "streaming"}>
  {markdown}
</Streamdown>;
```

`decorate` runs for each word while it animates. Return the same attributes for the same `text` and `seed`, because words re-render while they animate. Only `data-*` attributes are applied.

## Callbacks

Use `onAnimationStart` and `onAnimationEnd` to react to animation state changes. These fire when `isAnimating` transitions from `false` to `true` and vice versa. Both callbacks are suppressed in `mode="static"`.

```tsx title="app/page.tsx"
import { Streamdown } from "@lofcz/streamdown";
import "@lofcz/streamdown/styles.css";
import { useCallback } from "react";

export default function Page() {
  const handleAnimationStart = useCallback(() => {
    console.log("Streaming started");
  }, []);

  const handleAnimationEnd = useCallback(() => {
    console.log("Streaming ended");
  }, []);

  return (
    <Streamdown
      animated
      isAnimating={status === "streaming"}
      onAnimationStart={handleAnimationStart}
      onAnimationEnd={handleAnimationEnd}
    >
      {markdown}
    </Streamdown>
  );
}
```

Memoize callbacks with `useCallback` to avoid unnecessary effect re-runs.

## Advanced usage

For direct access to the rehype plugin (e.g. in custom pipelines), use `createAnimatePlugin`:

```tsx
import { createAnimatePlugin } from "@lofcz/streamdown/animate";

const animate = createAnimatePlugin({
  animation: "blurIn",
  duration: 200,
});

// animate.rehypePlugin is a standard rehype plugin
```

## Skipped elements

The animation skips text inside these elements to avoid breaking their layout:

- `<pre>` — preformatted / fenced code blocks (CommonMark always emits `pre > code`, so Shiki-highlighted blocks stay un-split)
- `<svg>` — vector graphics
- `<math>` — MathML elements
- `<annotation>` — MathML annotations

Inline `<code>` (backtick spans) **is** animated — wrapping words in style-inheriting spans is layout-neutral, same as surrounding paragraphs.

This means fenced code blocks, syntax-highlighted code, math equations, and diagrams render without animation spans, while inline code fades in with the prose.

## Fast-streaming models

Fast models can dump many tokens per React commit. The default 150ms duration with `animation-fill-mode: both` ensures words start invisible and end visible, making simultaneous mounts look intentional.

For smoother results with fast models:

- Use `blurIn` — blur masks batch arrivals better than opacity alone
- Increase duration slightly to 200-300ms
- Consider `ease-out` easing for a more natural deceleration

```tsx
<Streamdown
  animated={{
    animation: "blurIn",
    duration: 250,
    easing: "ease-out",
  }}
  isAnimating={status === "streaming"}
>
  {markdown}
</Streamdown>
```

## CSS custom properties

Each animated span receives these CSS custom properties via inline styles:

| Property | Description |
|----------|-------------|
| `--sd-animation` | The `@keyframes` name to use |
| `--sd-duration` | Animation duration |
| `--sd-easing` | CSS timing function |

The `[data-sd-animate]` selector in `styles.css` reads these properties:

```css
[data-sd-animate] {
  animation: var(--sd-animation, sd-fadeIn)
    var(--sd-duration, 150ms)
    var(--sd-easing, ease) both;
}
```

You can override these in your own CSS for more control.
